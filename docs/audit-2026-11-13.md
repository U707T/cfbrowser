## 2. 🔴 阻断性问题

### R1. 两套网络引擎并存，且新指纹能力只覆盖其中一条

- **位置**：`lib/services/network/adapters/platform_adapter.dart:181-193`（rhttp 优先）、
  `lib/services/network/adapters/rhttp_adapter.dart`（584 行）、
  `lib/pages/network_settings_page/widgets/engine_card.dart`
- **问题**：rhttp 直连自己握手、自己查 ECH；gateway 走 Rust 网关。两条路径的出口选择、
  ECH 钥匙、失败回退、TLS 指纹都不同。本次并入的「按 WebView 指纹握手」只在 gateway
  路径生效，rhttp 路径仍是 rustls 指纹。
- **为什么是问题**：同一 App 内两种 TLS 指纹、两套「隔夜连不上」的来源；上游
  `8ebb340f` 已整段删除（理由是重复引擎带来的故障面），本仓仍在维护 1.8k 行。
  这也是「CF 收紧握手后整站 403」在部分预设下依然会复现的原因。
- **修复建议**：单独一轮删除 rhttp（`git cherry-pick 8ebb340f` 后解 18 处冲突，主要是
  引擎选择 UI 与 l10n）。迁移策略：升级后「性能」预设自动切到网关，给一次 toast；
  隐藏的 `skipRhttpAdapter` 开关保留一个版本再删。
- **状态**：未修（刻意留待单独一轮，避免和指纹核心混在一起）

### R2. 加速核心落后上游 101 个提交（18 个子模块提交）

- **位置**：`core/doh_proxy`（c18d48d）、`lib/services/network/**`
- **问题**：上游 1.3.x 修的正是本仓的命门——CF 认握手指纹、VPN 让路后原生请求 403、
  占位钥匙导致安卓整站 502、安卓缺 `libc++_shared.so`。
- **为什么是问题**：不是「功能少」，是「明明有优选节点但站点整站 403」，且用户看到的是
  登录失败 / 图片全裂，不像网络引擎的问题。
- **修复建议**：本轮已一并处理；流程上每次上游发版后跑
  `git log --oneline <base>..upstream/main -- lib/services/network core/doh_proxy`
  过一遍，子模块单独一轮 + CI 验证，别和 Dart 侧混在一起。
- **状态**：**已修**（c18d48d → f584d0e，并入 8 条 Dart 提交，见 `docs/cfbrowser.md` §8）

## 3. 🟡 建议修复

### Y1. 系统返回手势把「后退」记成新导航，标签前进栈被截断

- **位置**：`lib/pages/webview_page.dart` `_handleBackNavigation`
- **问题**：直接 `controller.goBack()`，没有经过 `_goBack()` 设置 `_pendingTraversalTarget`；
  `recordNavigation(historyTraversal: false)` 会把前进历史截断。
- **影响**：用返回手势回退后，切标签重建 WebView，前进按钮消失（WebView 自身历史已丢）。
- **修复**：统一走 `_goBack()`。**已修**。

### Y2. 应用代理状态抛异常时变成未处理异步错误

- **位置**：`lib/services/network/doh/network_settings_service.dart` `_applyProxyState`
- **问题**：只有 `try/finally`，异常从 `_applyDebounce` 的 350ms 回调里冒出去没人接；
  `_pendingStart` / `isApplying` 也不会复位。
- **修复**：加 catch，标记启动失败、清 pendingStart、撤掉 WebView 代理。**已修**。

### Y3. URL 拦截对每次导航都等待代理启动

- **位置**：`lib/pages/webview_page.dart` `_shouldOverrideUrlLoading`
- **问题**：任何 http(s) 导航（含子框架）都 `await leaveStandby()`，首次进站内会先等网关
  起来再放行，白屏时间被放大。
- **修复建议**：只在 `navigationAction.isForMainFrame` 时 await，其余 `unawaited`
  （`onLoadStart` 里还会触发一次）。需要真机确认子框架时序，本轮未改。

### Y4. `network_settings_service.dart` 2,223 行、6 类职责

- **位置**：`lib/services/network/doh/network_settings_service.dart`
- **问题**：偏好读写、代理生命周期状态机（apply/standby/重启/复查）、WebView 代理、
  DoH 解析缓存、优选状态轮询、加速令牌轮询全在一个类里；改任何一处都要跑整套初始化。
- **修复建议**：拆 `ProxyLifecycleController`（apply / standby / webViewProxy）与
  `AccelAuthCoordinator`（令牌、路由表、上报），服务本身只保留偏好与 notifier。
  这是结构性欠债，建议在下次动网络设置前先拆。

## 4. 🔵 可选优化

- **B1**：加速范围页没有说明 `*.challenges.cloudflare.com` 永远走隧道
  （`core/doh_proxy/src/proxy.rs:1082-1090` 硬例外）。用户把 `cloudflare.com` 加进范围
  会以为被解密。建议在范围页脚注一句。
- **B2**：`browser_tabs_service._persist` 每次导航都全量序列化所有标签历史
  （最多 50×100 条 URL）并写 prefs。建议 500ms 节流合并写。
- **B3**：`ProxyLeafTrust._knownSiteHosts` 与 `BrowserScopeService.staticAssetHosts`
  重复维护 ldstatic 的四个主机；WPE 预放行漏一个就是子资源证书错误。合并成一处常量。

## 5. ✅ 做得好的地方

- **没有硬编码密钥**：全仓（`lib` / `packages` / `core` / `android`）扫 `ghp_`、
  `github_pat_`、私钥头、`AIza*`、`sk-*` 均无命中；token 只在 `/root/.github_token`。
- **证书信任是内容比对，不是盲放行**：`proxy_leaf_trust.dart` 用代理为某主机签发的叶子
  DER 精确比对，不一致按证书错误处理。
- **空范围防护**：`BrowserScopeService.setMitmHosts` 拒绝清空，因为 Rust 侧空范围 =
  「除 CF 验证域名外全部 MITM」，比默认更激进。
- **并发保护**：`_applyDepth` 重入保护 + 启动后复查 `_shouldRunProxyProcess`，
  避免设置往返时留下孤儿网关。
- 三个浏览器 service（范围 / 标签 / 快捷访问）职责单一、有测试，空列表、无痕不落盘、
  上限这些边界都处理了。

## 6. 跨模块观察

- 「刻意不改」的常量（MethodChannel 名、深链 scheme、原生文件名）散在
  `docs/cfbrowser.md` §2.1 与代码两处，改一处忘另一处就编译/运行失败。建议加一个测试
  断言这几个常量。
- `lib/config/sites/linuxdo.dart` 里的 `*.idcflare.com` **不是**双站残留，是照抄站点
  自己的链接安全信任列表，已核对。
- l10n 是生成代码（39k 行，占 `lib` 11%）：改完 arb 忘记跑
  `dart run tool/gen_l10n.dart` 会得到一堆「getter 不存在」的编译错误（本轮踩到）。
